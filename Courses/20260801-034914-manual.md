### 1. Архитектура и технические данные
**Стек:** n8n (автоматизация), Google Sheets (основная база данных и стейт-машина), Google Docs (генерация и хранение скриптов).

**Структура данных Google Sheets (дипломная таблица):**
*   **Лист `Videos`**: Содержит поля: `video_url` (ссылка на исходник), `summary` (реферат), `script_doc_url` (ссылка на Google Doc), `heygen_video_url` (финальный результат), `action_make_script`, `action_send_heygen`, `action_publish` (триггеры действий), `status` (статус выполнения).
*   **Лист `Settings`**: Хранит текущие параметры генерации: `avatar_id`, `voice_id`, `language`, `max_duration`, `prompt_style`.

**Интеграция с HeyGen:**
*   **API v3**: Использование эндпоинтов `GET /v3/avatars/looks` и `GET /v3/voices`.
*   **Авторизация**: API-ключ HeyGen: `[REDACTED]`.
*   **Механика:** n8n отправляет POST-запрос на создание видео, получает `video_id`. Статус отслеживается через Webhook (callback) или периодический опрос (polling) API через `GET` по `heygen_video_id` при отсутствии входящего события.

### 2. Принятые решения и обоснование
*   **Модель оплаты:** Переход на использование Pay-as-you-go API HeyGen без оформления платной подписки ($30/мес). *Обоснование:* Экономия бюджета до получения первых коммерческих заказов; соответствие архитектурным требованиям курса.
*   **Сохранение структуры:** Оставлена неизменной структура `Videos` (включая столбцы `action_...`), так как она является жестким требованием для сдачи дипломной работы.
*   **Переход на API v3:** Отказ от устаревших методов интеграции в пользу новых workflow преподавателя. *Обоснование:* Необходимость работы с обновленной инфраструктурой HeyGen для обеспечения стабильности системы.

### 4. План действий (To-Do)
1.  **Оптимизация workflow (приоритет):** Модифицировать текущие workflow преподавателя так, чтобы они не просто выводили данные в технический лист, а автоматически обновляли лист `Settings` дипломной таблицы (`avatar_id`, `voice_id`). Это исключит ручной перенос данных.
2.  **Завершение обучения:** Прохождение этапа настройки HTTP-запросов и обработки callback-ответов от HeyGen.
3.  **Рефакторинг (post-diploma):** После сдачи проекта реализовать архитектуру "универсального оркестратора". Введение поля `generator` в `Settings`, что позволит переключаться между `HeyGen`, `OmniHuman 5.1` (Kie.ai) и другими сервисами через единый интерфейс n8n.

### 5. Нерешенные вопросы и риски
*   **Ограничения API:** Существует риск, что определенные премиальные аватары (Digital Twins), доступные в веб-интерфейсе при наличии активной подписки, могут быть недоступны через API-only аккаунт (Pay-as-you-go).
*   **Технический долг:** Текущие workflow преподавателя требуют ручного вмешательства для настройки (копирование параметров). Необходимо автоматизировать процесс обновления `Settings` из ответа API.
*   **Сложность миграции:** При переходе на `OmniHuman 5.1` потребуется внедрение промежуточного TTS-движка, так как OmniHuman работает в связке "фото + аудио", в отличие от HeyGen, который принимает текст напрямую. Это потребует усложнения цепочки нод n8n.
