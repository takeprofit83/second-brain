# Проектирование Context Resume Pipeline (Фаза 1)

> **Статус:** Фаза 1 — Проектирование (до утверждения пользователем)  
> **Версия документа:** 1.0 (23 октября 2026 г.)  
> **Цель:** Минимальный, безопасный и проверяемый конвейер передачи рабочего контекста между ChatGPT, Claude, DeepSeek и Gemini без прямого вмешательства в DOM чатов и без секретов в коде букмарклета.

---

## 1. Сценарий использования (End-to-End User Flow)

```
[Пользователь в любой вкладке: ChatGPT / Claude / DeepSeek / Gemini]
                           │
                           ▼
  1. Клик по букмарклету "Atlas: Подхватить контекст"
     (в коде букмарклета НЕТ секретов; только вызов окна Relay)
                           │
                           ▼
  2. Открывается всплывающее окно Relay (tangerine-vps)
     - Проверка сессии (PIN / Master-токен в sessionStorage)
     - Выбор проекта: [Atlas] [Курс] [Настя] [Дача]
                           │
                           ▼
  3. Relay отправляет авторизованный POST-запрос в n8n:
     URL: https://n8n.neiroclone.ru/webhook/atlas-context-resume
     Headers: X-Atlas-Secret: <секрет из защищённого хранилища Relay>
     Body: { "project": "atlas" }
                           │
                           ▼
  4. n8n Workflow "Atlas - Context Resume":
     - Валидирует секрет и имя проекта.
     - Запрашивает через GitHub API список файлов в Projects/<project>/logs/.
     - Находит самый свежий .md (исключая -raw.md).
     - Считывает содержимое и валидирует 10 обязательных полей Handoff.
     - Формирует стартовый промпт передачи для новой модели.
     - Возвращает структурированный JSON.
                           │
                           ▼
  5. Окно Relay отображает результат:
     - Проект: Atlas | Обновлено: 2026-09-21 20:47:47 | Версия: ...
     - Следующий шаг: "..."
     - Большая кнопка: [ 📋 Скопировать контекст в буфер ]
                           │
                           ▼
  6. Пользователь нажимает "Скопировать", переключается в окно новой модели
     и нажимает Ctrl+V (вставка в поле ввода).
     (Никакой автоотправки сообщений от имени пользователя).
```

## 2. Спецификация Handoff-документа (10 обязательных полей)

Чтобы контекст гарантированно позволял любой модели продолжить работу без потери деталей, n8n собирает ответ строго по следующей схеме:

| № | Поле | Назначение | Пример значения |
| :--- | :--- | :--- | :--- |
| 1 | `project_id` & `project_name` | Идентификатор и имя проекта | `atlas` / `Atlas: AI-OS & Automation Engine` |
| 2 | `updated_at` | Дата и время фиксации среза | `2026-10-23 05:20:00` |
| 3 | `goal` & `current_state` | Цель и текущее состояние | `Цель: бесшовный перенос контекста. Состояние: Фаза 1 спроектирована.` |
| 4 | `confirmed_decisions` | Подтверждённые решения (ADR) | `ADR-001 (Адаптеры), ADR-014 (Relay postMessage для Context Resume)` |
| 5 | `constraints` | Действующие ограничения | `Без секретов в URL, без сторонних пакетов, без автоотправки в чат` |
| 6 | `completed_actions` | Что проверено end-to-end | `Аудит инфраструктуры, создание проектных документов docs/` |
| 7 | `open_questions` | Открытые вопросы и риски | `Статус Яндекс Облака, дефолтный провайдер для рутины` |
| 8 | `next_step` | Следующий конкретный шаг | `Согласование Фазы 1, импорт воркфлоу в n8n` |
| 9 | `key_documents` | Ссылки на ключевые файлы | `docs/ARCHITECTURE.md`, `second-brain/docs/DECISIONS.md` |
| 10 | `context_source` & `version` | Источник и хэш/имя файла | `Projects/Atlas/logs/20260921-204747-diagnostic-audit.md` (v0.3.1) |

## 3. Спецификация API и сетевого взаимодействия

### Маршрут n8n:
* **Эндпоинт:** `POST https://n8n.neiroclone.ru/webhook/atlas-context-resume`
* **Аутентификация:** Заголовок `X-Atlas-Secret` (Header Auth).
* **Формат запроса (Request Body):**
  ```json
  {
    "project": "atlas"
  }
  ```
  *(Допустимые значения `project`: `atlas`, `courses`, `dacha`, `nastya`)*

* **Формат успешного ответа (Response 200 OK):**
  ```json
  {
    "status": "ok",
    "project": "atlas",
    "filename": "20260921-204747-diagnostic-audit-20260921-kie-final.md",
    "updated_at": "2026-09-21 20:47:47",
    "version": "20260921-204747",
    "summary": {
      "goal": "...",
      "current_state": "...",
      "next_step": "..."
    },
    "prompt": "Ты продолжаешь работу над проектом Atlas...\n\n### 1. Текущее состояние...\n### 2. Принятые решения...\n..."
  }
  ```

* **Формат ошибки (Response 400/401/404):**
  ```json
  {
    "status": "error",
    "message": "Project not found or no logs available"
  }
  ```

## 4. Архитектура безопасности

1. **Исключение секретов из кода букмарклета:**
   Букмарклет содержит только безопасный URL вызова Relay:
   `javascript:(function(){window.open('https://relay.domain/atlas-relay.html?action=resume','atlas_resume','width=480,height=520');})();`
   В коде букмарклета нет API-ключей, токенов GitHub или секретов n8n.
2. **Исключение секретов из URL:**
   Никакие токены не передаются в параметрах адресной строки (`?token=...`).
3. **Хранение авторизации в Relay:**
   Пользователь вводит мастер-код (PIN/пароль) один раз за сессию в окне Relay. Он сохраняется исключительно в `sessionStorage` домена Relay. При закрытии браузера сессия сбрасывается.
4. **Контроль доступа к данным:**
   Вебхук n8n выдаёт данные **только из каталогов логов** (`Projects/<project>/logs/` и `Courses/`). Доступ к корневым файлам, `.env`, ключам SSH и конфигам n8n через этот вебхук физически невозможен (жестко захардкоженный путь поиска в нодах GitHub API).
5. **Аварийный выключатель (Kill Switch):**
   При подозрении на утечку или скомпрометированный доступ вебхук деактивируется одним кликом в n8n UI (переключатель `Active` -> `Inactive`), что сразу даёт ответ `404 Not Found` на любые запросы.

## 5. Предотвращение конфликтов версий и тихой перезаписи

1. **Принцип Read-Only в Фазе 1:** Конвейер Context Resume выполняет только чтение. Он физически не имеет нод на запись или модификацию файлов.
2. **Фиксация родительской версии (Handoff Lineage):**
   В выдаваемый промпт явно зашивается метаданная: `Контекст основан на версии: {filename}`.
3. **Защита при последующем сохранении (Write Pipeline):**
   Существующий воркфлоу захвата (`atlas-capture`) формирует файлы с уникальным штампом времени (`{yyyyLLdd-HHmmss}-{source}`). Даже если две модели одновременно отправят обновления, они запишутся как два независимых файла с разными штампами времени, исключая тихую перезапись.
4. **Явное подтверждение пользователя:**
   Никакие данные не сохраняются автоматически в фоновом режиме без явного клика пользователя по кнопке отправки в Relay.
