# Сессия: расширение capture-пайплайна на новые папки (Настя, Дача)

Конспект для передачи контекста другой модели/агенту без доступа к этой переписке. Сессия шла в рабочей директории `AI_AGENTS` (не `Atlas`), но весь фактический труд — над проектом Atlas/second-brain.

## С чего начался разговор

Пользователь (Telegram-бот AI_AGENTS) спросил про хранение переписок «из этого и других чатов». В ходе уточнения выяснилось, что задача шире: настроить хранение и резервное копирование из всех папок/чатов/директорий в единую базу, возможно на Obsidian — и что об этом уже есть сохранённый диалог с ChatGPT в проекте Atlas.

Обнаружено: такая система уже построена — `second-brain` (GitHub `takeprofit83/second-brain`), структура папок уже под Obsidian-vault (Knowledge/Courses/Projects/Resources/Templates), плюс n8n-пайплайн захвата переписок из ChatGPT/Gemini/Qwen/DeepSeek через букмарклеты + relay-страницу на отдельном VPS. `Projects/Atlas/atlas-model-roles-pipeline.md` — по всей видимости конспект того самого исходного диалога с ChatGPT (загружен в репозиторий вручную, коммит `5adbd96`, "Add files via upload").

Боты в AI_AGENTS (этот Claude-бот, gemini-bot, qwen-bot, salon-bot) в этот пайплайн **не подключены** — их история чата живёт только в памяти процесса (`Map` в `src/bot.js`), теряется при рестарте. Это отдельная, ещё не решённая часть исходного запроса — см. «Что осталось» ниже.

## Задача, которую решали: кнопки «Настя» и «Дача»

Пользователь: «сделали мини-проект для снимков переписок, добавили 2 варианта (Atlas, Курс), нужно добавлять ещё кнопки для новых папок — сейчас есть папка Настя, есть папка Дача».

### Как было устроено раньше

`project` — поле, введённое ранее (§31 в `Atlas_Technical_Documentation.md`), но реализованное как **жёсткий бинарный тернарник** в трёх местах workflow `Atlas - Kie Adapter` (id `ls5hJoxIFtUycpKH`):
- `Edit Fields` (Set-нода): `project = (Проект === "Курс" || body.project === "courses") ? "courses" : "atlas"`
- `Create a file` (GitHub-нода, коммитит финальный конспект): `filePath = (project === "courses" ? "Courses/" : "Projects/Atlas/logs/") + ...`
- `Save Raw` (GitHub-нода, коммитит сырой текст): та же логика, независимо от Create a file (не через `Combine Chunks`, а напрямую из `$json`)
- `On form submission`: dropdown «Проект» только с опциями Atlas/Курс

Добавление третьего/четвёртого варианта в такую схему means переписывать все три тернарника заново под каждую новую папку — не масштабируется.

### Решение (архитектурный выбор, принят и реализован)

Заменили тернарники на **словарь `project-key → путь`** во всех трёх местах, с fallback на `"Projects/Atlas/logs/"` (сохраняет обратную совместимость со старыми интеграциями, которые ещё не шлют `project`):

```js
// Edit Fields — нормализация ключа из формы (кириллица) или из body.project (уже ключ)
({"Курс":"courses","Настя":"nastya","Дача":"dacha","Atlas":"atlas"})[$json["Проект"]] || $json.body?.project || "atlas"

// Create a file / Save Raw — маппинг ключа на путь
({"courses":"Courses/","nastya":"Projects/Nastya/logs/","dacha":"Projects/Dacha/logs/"}[project] || "Projects/Atlas/logs/")
```

`On form submission` → dropdown «Проект» получил опции `Настя`/`Дача`.

Relay-страница (`atlas-relay-page-REAL-SECRET.html`, источник лежит в `Atlas/` рядом с second-brain, деплоится на `tangerine-vps` в `/var/www/html/atlas-relay-d42332f0300f625f.html`) была со статичными 2 кнопками (Atlas/Курс) — переписана на **данные вместо разметки**: массив `PROJECTS = [{key, label, color}, ...]`, кнопки рендерятся циклом. Сейчас 4 записи (atlas/courses/nastya/dacha). Новая папка в будущем = одна строка в массиве + одна строка в словаре на стороне n8n — без переписывания условий.

## Грабли, найденные по пути (для памяти проекта)

- **n8n `PUT /api/v1/workflows/{id}` отклоняет `settings`, если в нём есть недокументированные поля.** GET-ответ вернул `settings: {executionOrder, binaryMode, availableInMCP}` — отправка этого же объекта в PUT дала `400 "request/body/settings must NOT have additional properties"`. Фикс: перед PUT обрезать `settings` до только задокументированных полей (в данном случае — оставить только `executionOrder: "v1"`). Похоже, GET и PUT работают по разным схемам валидации в этой версии n8n.
- **У этого n8n нет `GET /api/v1/api-keys`** (self-service список/удаление ключей через публичный API) — вернул `404 "not found"`. Отозвать API-ключ можно только вручную через UI (Settings → n8n API). Ключ, который использовался в этой сессии, создан пользователем с TTL 7 дней и решено не отзывать вручную — истечёт сам.
