Принято. Контекст проекта **Atlas (Контент-завод)** зафиксирован. 

Для следующей модели: текущая итерация остановилась на этапе интеграции HeyGen API с оркестратором n8n в рамках дипломной архитектуры. Система находится в состоянии «интеграция проведена, но требует доработки процесса передачи параметров между таблицами и API».

---

### Архитектурный слепок для продолжения (резюме)

#### 1. Инфраструктура
*   **Orchestrator:** n8n (self-hosted или cloud, работа через HTTP Request узлы).
*   **Source of Truth:** Google Sheets («Дипломная таблица»).
    *   `Videos` — очередь обработки с полями для API-статусов.
    *   `Settings/Avatars/Voices` — справочники конфигураций, заполняемые через API-скрипты.
*   **External API:**
    *   **HeyGen:** Токен [REDACTED]. Режим работы — Pay-as-you-go. Используются эндпоинты `/v3/avatars/looks` и `/v3/voices` для синхронизации ID.

#### 2. Текущий статус логики
*   **Что работает:** 
    *   Скрипты получения списков доступных аватаров и голосов (workflow преподавателя).
    *   Механизм восстановления URL через polling (workflow «Восстановление URL видео»).
*   **Что вызывает сложности:** 
    *   Разрыв между справочниками и рабочей таблицей `Videos` (требуется ручной перенос ID аватара/голоса в строку задачи).
    *   Необходимость создания «заглушки» для тестирования логики без списания API-кредитов.

#### 3. Roadmap для следующей модели
1.  **Автоматизация справочников:** Реализовать передачу выбранного аватара из листа `Settings` напрямую в пайплайн генерации через n8n (Lookup или Set ноды).
2.  **Реализация "Stub-режима":** Создать в n8n переключатель (например, `production_mode = false`), при котором вместо реального POST-запроса к HeyGen генерируется эмулированный JSON-ответ с фиктивным URL.
3.  **Оптимизация:** Переход к "генератор-агностик" архитектуре: абстрагировать параметры аватара так, чтобы замена HeyGen на другого провайдера требовала смены параметров в таблице, а не изменения структуры workflow.

#### 4. Известные ограничения
*   **Бизнес-ограничение:** Отсутствие подписки в HeyGen ограничивает функционал личного кабинета, работа возможна только через API.
*   **Технический долг:** Жесткая привязка к структуре дипломной Google-таблицы. Любое отклонение от схемы колонок может привести к сбою автоматизации, проверяемой преподавателем.
*   **Безопасность:** Ключ HeyGen [REDACTED] требует осторожного использования в логировании n8n (необходимо проверять настройки вывода логов в нодах HTTP Request).
