Вот краткий конспект проведенной настройки интеграции:

### 1. Обсуждаемые темы
*   Настройка `Workflow Input Schema` для суб-workflow.
*   Передача параметров (`user_input` и `system_prompt`) из основного workflow в суб-workflow через ноду `Call 'Atlas-Kie Adapter Core'`.
*   Активация workflows для проведения финального тестирования.

### 2. Принятые архитектурные решения
*   **Ручное определение полей:** Вместо автоматического определения выбрано ручное создание полей `user_input` (тип String) и `system_prompt` (тип String) в схеме суб-workflow для обеспечения стабильности передачи данных.
*   **Маппинг данных:** Использование выражений `{{ $json.user_input }}` и `{{ $json.system_prompt }}` в ноде вызова для обеспечения динамической передачи контента.

### 3. Найденные ошибки и их решения
*   **Проблема:** Отсутствие полей в ноде вызова суб-workflow.
    *   *Решение:* Перезагрузка/обновление схемы в суб-workflow, после чего поля корректно отобразились в родительской ноде.
*   **Проблема:** Workflow был неактивен после внесения правок.
    *   *Решение:* Включение переключателя `Active` в основном workflow для обеспечения работы через форму.

### 4. Незакрытые вопросы
*   **Ожидание:** Успешное прохождение тестового запроса через форму и проверка передачи данных в GitHub.
*   *Статус:* Ожидается подтверждение от пользователя об отправке тестового сообщения.
