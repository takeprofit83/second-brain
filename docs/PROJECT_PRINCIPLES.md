# Second Brain + Atlas — инженерные принципы проекта

## Общая идея

Проект состоит из двух уровней.

**Second Brain** — это центральный репозиторий знаний проекта и единственный источник истины.

**Atlas** — инженерная платформа (automation engine), входящая в состав Second Brain. Она отвечает за обработку данных, взаимодействие с AI-провайдерами, извлечение знаний, маршрутизацию запросов и сохранение результатов.

Second Brain определяет правила и знания проекта.
Atlas реализует их технически.

## Главный принцип

История чатов не является источником истины.

Приоритет источников информации всегда следующий:

1. Репозиторий проекта.
2. Документация.
3. Workflow.
4. Исходный код.
5. История переписки (только если изменения ещё не перенесены в репозиторий).

Если документация противоречит чату — доверять документации.

## Роль AI

Любой AI рассматривается как инженер команды.
Его задача — понимать существующую систему, а не придумывать новую.

Перед любым предложением необходимо:

1. изучить документацию;
2. изучить workflow;
3. понять причины существующей реализации;
4. только затем предлагать изменения.

Запрещено переписывать архитектуру без анализа текущей.

## Архитектурные принципы Atlas

Atlas строится как модульная система.
Каждый модуль имеет одну ответственность.

Не допускаются:

- дублирование логики;
- копирование промптов;
- смешивание нескольких обязанностей в одном workflow;
- зависимость архитектуры от конкретной модели AI.

## Adapter Architecture

Каждый AI-провайдер реализуется отдельным Adapter Core.

Например:

- Atlas-Kie Adapter Core
- Atlas-OpenRouter Adapter Core
- Atlas-Claude Adapter Core
- Atlas-GPT Adapter Core

Все Adapter Core обязаны иметь одинаковый контракт.

Оркестратор знает только:

- provider;
- system_prompt;
- user_input.

Выбор адаптера выполняет Router.
Оркестратор никогда не содержит логики конкретного AI.

## Workflow

Каждый workflow должен решать только одну задачу.

Примеры:

- Adapter Core
- Router
- Docs Sync
- Logger
- Relay

Если workflow начинает выполнять несколько независимых функций — это повод разделить его.

## Документация

Документация является частью проекта.
После любого значимого изменения она должна обновляться.
Документация важнее истории переписки.

## Логи

Все важные выполнения должны сохраняться.

Предпочтительный формат:

- Markdown;
- GitHub;
- локальный архив (при необходимости).

## Стиль разработки

Приоритеты:

- читаемость выше краткости;
- минимальное дублирование;
- независимые небольшие модули;
- единый стиль именования;
- предсказуемая архитектура.

## Назначение Second Brain

Second Brain — это персональная операционная система знаний (Personal Operating System).
Его задача — хранить архитектуру проекта, документацию, workflow, промпты, накопленные знания и обеспечивать единый контекст для всех AI-ассистентов.
Atlas является одним из модулей этой системы.

## Ожидаемое поведение AI

Во время работы придерживайся следующего порядка:

1. Сначала анализ.
2. Затем понимание существующей реализации.
3. После этого — рекомендации.
4. Любые изменения должны соответствовать архитектурным принципам проекта.
5. Не изобретай новую архитектуру, если существующая ещё не изучена.

Главная цель — эволюционно развивать систему, сохраняя её целостность, а не переписывать её заново.
