# AI-OS Security & Threat Model (Политика безопасности и модель угроз)

**Версия:** 1.0  
**Дата:** 2026-10-23  
**Статус:** Действующий регламент безопасности  

---

## 1. Архитектурные принципы безопасности

1. **Принцип минимальных привилегий (Principle of Least Privilege):**
   - Расширение запрашивает доступ только к явно перечисленным доменам LLM (`host_permissions`) и активной вкладке (`activeTab`).
   - GitHub Personal Access Token (PAT) имеет доступ только к репозиторию `second-brain` и не имеет прав администратора организации.
2. **Изоляция секретов от клиентской части:**
   - Постоянные API-ключи провайдеров (OpenRouter, Polza.ai, Kie.ai, GitHub PAT) **никогда** не передаются в браузер и не хранятся в коде расширения или релея.
   - Все обращения к внешним платным API и хранилищу выполняет сервер автоматизации n8n (`nikita-vm`) из доверенной внутренней сети.
3. **Защита вебхуков (Header Authentication):**
   - Все входящие вебхуки n8n (`atlas-context-resume`, `atlas-reverse-save`, `atlas-wiki-query`, `atlas-capture`, `atlas-docs-sync`) защищены обязательным заголовком `X-Atlas-Secret`.
   - Любые запросы без корректного секрета немедленно отклоняются со статусом `401 Unauthorized` до запуска логики воркфлоу.
4. **Недопущение утечки секретов в Git:**
   - Репозиторий `second-brain` не содержит открытых паролей, токенов или приватных ключей.
   - Секреты хранятся в защищённом локальном хранилище KeePass (`atlas-secrets.kdbx`) и в зашифрованных сущностях n8n (`credentials_entity`).
   - В логах и документации используется маскирование: `[REDACTED]`.

## 2. Анализ модели угроз (STRIDE Threat Model)

| Угроза (STRIDE) | Сценарий атаки | Мера противодействия в AI-OS | Статус |
|---|---|---|---|
| **Spoofing (Подмена)** | Сторонний субъект пытается отправить фиктивный отчёт или получить чужой контекст | Валидация заголовка `X-Atlas-Secret` на уровне n8n; проверка `project_id` по белому списку разрешённых проектов. | PASS |
| **Tampering (Искажение)** | Попытка перезаписать существующий файл сессии другим содержимым | Логи сессий именуются по строгому монотонному шаблону `YYYYMMDD-HHmmss-<source>-<task>.md`. Каждая запись создаёт новый файл, перезапись исключена. | PASS |
| **Repudiation (Отказ)** | Модель или оператор не могут подтвердить происхождение решения | Каждый лог содержит поле `source_ai`, временную метку ISO 8601, уникальный `task_id` и фиксируется в Git с хэшем коммита. | PASS |
| **Information Disclosure (Утечка)** | Перехват контекста или ключей через CSP / сниффинг | Все коммуникации с n8n защищены HTTPS с TLS-сертификатом Let's Encrypt; CSP браузера изолирует контекст вкладки. | PASS |
| **Denial of Service (DoS)** | Флуд вебхуков длинными текстами | n8n имеет ограничения размера тела запроса и таймауты (15-30 с); чанкинг и валидация схемы перед отправкой в LLM. | PASS |
| **Elevation of Privilege (Эскалация)** | Выход из песочницы проекта в системные папки сервера | Воркфлоу строго маппят `project_id` на предопределённые подпапки `Projects/<id>/logs/`; обращение к системным путям блокируется регулярным выражением. | PASS |

## 3. Регламент работы с секретами

1. **Ротация секрета вебхуков (`X-Atlas-Secret`):**
   - При необходимости смены секрета генерируется новая 64-символьная шестнадцатеричная строка: `openssl rand -hex 32`.
   - Значение обновляется в n8n (Credentials -> `atlas capture secret`) и в расширении (`chrome.storage.local` / `popup.js`).
2. **Ротация GitHub PAT:**
   - Создаётся Fine-grained Personal Access Token с правами `Contents: Read and write` только для `takeprofit83/second-brain`.
   - Значение обновляется в n8n (Credentials -> `atlas github token`).
