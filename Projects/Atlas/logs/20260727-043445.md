### 1. Архитектурный стек
*   **Хост:** Ubuntu 24.04.4 LTS (VPS: 4 vCPU, 3.8 GB RAM).
*   **Оркестрация:** Docker Engine + Docker Compose.
*   **Сеть:** Выделенная Docker-сеть `apps` (тип `external`).
*   **Сервисы:**
    *   **n8n (v2.31.6):** Ядро автоматизации (порт 5678, внутренняя сеть).
    *   **PostgreSQL (17-alpine):** База данных n8n (пароль: `K8xP4mR7vN2qL89`, БД: `n8n`).
    *   **Redis (8-alpine):** Очереди и кэширование n8n.
    *   **MinIO (RELEASE.2023-06-23T20-26-00Z):** Объектное хранилище (адаптировано под старый CPU, пароль: `R7mK9xP2vL8qN4tH`).
    *   **Nginx Proxy Manager:** Проксирование и SSL (настройка завершена).
*   **Репозиторий:** `github.com/takeprofit83/second-brain` (структура папок: `/knowledge`, `/learning`, `/projects`, `/mistakes`, `/templates`, `/assets`).

### 2. Принятые решения и обоснование
*   **Принцип "Независимости от плагинов":** Для ключевых интеграций с LLM-провайдерами (Kie.ai и др.) решено использовать **HTTP Request** вместо нативных нод. Это обеспечивает переносимость системы, контроль над API-запросами и упрощает миграцию между провайдерами в будущем.
*   **Архитектурный подход:** Проект строится не как «заметки», а как **Knowledge OS** (инженерная операционная система), автоматизирующая процесс сохранения контекста работы AI-агентов.
*   **Методология:** Разделение ролей (ChatGPT — архитектор, Claude Code — инженер-исполнитель). Приоритет — создание документации «как код» и автоматизация workflow через n8n.

### 3. Текущий статус инфраструктуры и работ
*   **Готово (End-to-End):**
    *   Сервер настроен и защищен (SSH, ключи).
    *   Стек контейнеров запущен в единой сети `apps`.
    *   GitHub CLI интегрирован, структура папок проекта зафиксирована в Git.
    *   n8n настроен с PostgreSQL и Redis.
    *   Создана форма ввода (`Form Trigger`) для сбора контекста диалогов («Second Brain Input»).
*   **В процессе:**
    *   Отладка записи файлов внутри контейнера n8n.
    *   Настройка HTTP-адаптера для вызова API LLM-провайдеров.
*   **Нерешённые вопросы:**
    *   Разрешение прав доступа (permissions) для записи логов/файлов из контейнера n8n в примонтированные тома.
    *   Тестирование записи workflow-файлов в папку проекта через API или системные команды.

### 4. План следующих шагов
1.  **Завершение отладки прав:** Проверка прав доступа в `ls -ld /tmp` и `/home/node` для реализации стабильной записи метаданных текущего сеанса.
2.  **Реализация HTTP-адаптера:** Создание универсального узла `HTTP Request` в n8n для взаимодействия с LLM (на примере Kie.ai).
3.  **Автоматизация контекста:** Создание workflow, который принимает текст из `Form Trigger`, отправляет его в LLM для структурирования (в формате Markdown) и сохраняет полученный результат в репозиторий `second-brain` (через Git или API GitHub).
4.  **Финальная сборка:** Создание итоговой базы знаний/шпаргалки (Infrastructure/2026-07-24-server-setup.md).

### 5. Известные ограничения
*   **CPU:** Использование специфических образов Docker (MinIO) из-за ограничений процессора VPS (отсутствие `x86-64-v2`).
*   **Контекст:** Необходимо строго следовать формату «История проекта», чтобы избежать деградации качества работы AI-моделей при передаче контекста.
