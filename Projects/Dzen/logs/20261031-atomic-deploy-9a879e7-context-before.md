Новый stella-reservation.ts: checkout и fulfillment используют одну транзакционную DB-row lock (AppSetting stella_inventory_lock). Остаток для продажи перечитывается из сохранённых балансов читателей, обязательств клиентских каналов и резервов внутри транзакции, а не из UI-кэша. Резерв создаётся до внешнего createYookassaPayment; локальный UUID передаётся как idempotenceKey и metadata.reservationId. Строгая проверка count и tenant/channel перед оплатой.

Новые резервы durable, без автоматического15-минутного снятия: открытый платёж всё ещё может быть оплачен. При потерянном ответе резерв остаётся, клиент получает reservationId для разбора. На подтверждённом начислении резерв конвертируется в баланс атомарно, под тем же lock. Подтверждённая API-отмена освобождает резерв через webhook и сверку последних платежей. Уведомлению без перепроверки API не доверяем. Старые15-минутные холды читаются по прежнему контракту.
