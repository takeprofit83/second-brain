## 🔄 Как устроен цикл совместной работы с ИИ

1. **Человек (Вы):** Открываете эту базу в **Obsidian** (папка `second-brain` как Vault), читаете заметки, редактируете цели, смотрите граф связей.
2. **Браузерные агенты (ChatGPT, Claude, DeepSeek, Gemini, Kimi):**
   - Получают контекст проекта через **Atlas Companion Extension** (вкладка *«Подхватить»*).
   - В промпте получают строгую директиву: **не переспрашивать**, а сразу выполнять *«Следующий конкретный шаг»*.
   - Выполняют работу и передают отчёт через вкладку *«Сохранить отчёт»* в n8n `atlas-reverse-save`.
3. **Локальные агенты (Claude Code CLI, Antigravity IDE, Cursor):**
   - Запускаются прямо в папке проекта на ПК.
   - Используют CLI-утилиту `ai-os resume <проект>` и сохраняют результаты через `ai-os save <проект>`.
   - Автоматически коммитят и пушат результат в GitHub.
4. **Сквозная синхронизация:** Локальный фоновый синхронизатор (`tools/sync-watch.ps1`) подтягивает любые внешние коммиты за 30 секунд — Obsidian всегда показывает актуальную картину!

## 🏷 Модель памяти и экономия токенов (Obsidian Properties)

Чтобы ИИ не тратили лишние токены и не читали всю историю прошлых диалогов, введена трёхслойная маркировка (ADR-018):

- 🟢 **Tier 1 (Core Memory / MOC):** Свойства `type: memory`, `tier: 1`, `ai_read: true`, теги `#memory`, `#moc`.
  - Файлы `project_state.md`. Агенты читают **только** их на старте (< 150 строк / ~1,200 токенов). Вся история сжата в текущий срез и очередь `next_steps`.
- 🟡 **Tier 2 (Reference Knowledge):** Свойства `type: knowledge`, `tier: 2`, `ai_read: on_demand`.
  - Заметки `Knowledge/*.md` и ADR. Читаются точечно только по явным `[[ссылкам]]` из Tier 1.
- 🔴 **Tier 3 (Logs Archive):** Свойства `type: log`, `tier: 3`, `ai_read: false`.
  - Папки `logs/`. **Строгий запрет на массовое чтение.** Архив только для записи и аудита.
