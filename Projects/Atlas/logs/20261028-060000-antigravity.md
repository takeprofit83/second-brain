### Б. Устранение проблемы с передачей контекста в Claude (Desktop & Code)
1. **Диагностика:** Выявлена точная причина, почему Claude Desktop «был не в курсе»:
   - Claude Desktop (MSIX) работал в изолированной песочнице без локального доступа к файлам;
   - Конфигурационный файл `claude_desktop_config.json` отсутствовал на машине;
   - Claude Code работал в каталоге `Content-fabric`, где не было инструкций Second Brain.
2. **Реализация нативного MCP-моста:**
   - Создан и внедрён Python-сервер MCP: `second-brain/tools/mcp_server.py`.
   - Зарегистрированы 4 инструмента: `ai_os_resume_context`, `ai_os_save_session`, `ai_os_status`, `ai_os_read_file`.
   - Настроен `claude_desktop_config.json` для Claude Desktop (включая `@modelcontextprotocol/server-filesystem` для диска `D:\`).
   - Claude Code подключен к `second-brain` на системном уровне (`--scope user` в `.claude.json`).
   - Созданы глобальные правила `~/.claude/CLAUDE.md` и локальные правила `D:\YandexDisk\Content-fabric\CLAUDE.md`.

## 2. Принятые архитектурные решения
- **ADR-019 (MCP Bridge for AI Agents):** Любой локальный агент (Claude Desktop, Claude Code, Cursor) получает доступ к Second Brain через стандартизированный протокол MCP, исключая необходимость ручной передачи файлов пользователем.
- **Двухуровневая фиксация памяти:**
  - `project_state.md` (Tier 1) хранит только актуальное резюме (<150 строк) и активные шаги.
  - Детальные выкладки фиксируются в `Knowledge/*.md` (Tier 2), доступных по прямым вики-ссылкам.
