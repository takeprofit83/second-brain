### 1. Текущий статус проекта и архитектура
Проект представляет собой автоматизированный конвейер видеопроизводства, работающий на базе **n8n** как оркестратора и **Google Sheets** как единого источника данных и панели управления (Dashboard).

*   **Структура данных Google Sheets:**
    *   Лист `Videos`: содержит очередь задач. Ключевые столбцы: `video_id`, `prompt/script`, `status`, `heygen_video_id`, `heygen_video_url`, `action_send_heygen`.
    *   Лист `Settings`: содержит конфигурационные параметры (`avatar_id`, `voice_id`, API-токены).
*   **Стек технологий:**
    *   **Orchestration:** n8n (версия, поддерживающая API v3).
    *   **Video Engine:** HeyGen API (v3).
    *   **Data Layer:** Google Sheets API.
*   **Статус готовности:** 
    *   Реализован базовый CRUD для Google Sheets.
    *   Настроена аутентификация в n8n через Credentials (Header Auth, Bearer Token: `[REDACTED]`).
    *   Workflow для извлечения метаданных (аватары/голоса) функционирует.
    *   Механизм опроса (polling) статуса готовности видео через `heygen_video_id` реализован и протестирован.

### 2. Принятые решения и обоснование
1.  **Приоритет HeyGen API v3:** Выбран в качестве основного, так как он обеспечивает стабильность для дипломной работы и является целевым для текущего курса. Использование v3 гарантирует актуальность API-методов.
2.  **Использование n8n Webhooks/Polling:** Решено использовать комбинированный подход: основной поток ожидает Webhook, но реализован "предохранитель" в виде polling-workflow. Это необходимо для обеспечения отказоустойчивости при кратковременных сбоях интернет-соединения или сбросе вебхуков.
3.  **Разделение задач:** Внедрена архитектура "Модуль-переключатель" (логически), где HeyGen является основным модулем. Это позволяет в будущем заменить его на альтернативы (Kie.ai/OmniHuman) без переработки структуры Google Sheets, изменив только блок внутри n8n.
4.  **Соблюдение ограничений диплома:** Принято решение не менять названия ключевых столбцов (`action_send_heygen`, `heygen_video_url`) для исключения конфликтов с системой проверки преподавателя.

### 4. План следующих шагов
1.  **Оптимизация передачи данных:** Автоматизировать перенос значений `avatar_id` и `voice_id` из промежуточной таблицы напрямую в `Settings` через n8n (уйти от ручного копирования).
2.  **Обработка ошибок:** Добавить блок `Error Trigger` в n8n для отправки уведомлений (в Telegram или на e-mail) при сбоях генерации видео (статус `FAILED`).
3.  **Валидация скриптов:** Внедрить промежуточный этап проверки длины текста скрипта перед отправкой в HeyGen (учет ограничений символов API).
4.  **Финальная очистка:** Настройка жизненного цикла строк — перемещение завершенных задач в архивный лист `Archive` для оптимизации скорости работы API Google Sheets.

### 5. Нерешенные вопросы и ограничения
*   **Ограничение по времени:** Обработка видео в HeyGen может занимать от 5 до 20 минут. Текущая система polling настроена с интервалом, необходимо сбалансировать его, чтобы не исчерпать лимиты API n8n (если используется cloud-версия).
*   **Масштабируемость:** При большом количестве строк (более 500) API Google Sheets может начать возвращать ошибки Rate Limit. Рекомендуется добавление `Wait` узлов между запросами.
*   **Секреты:** Все токены API (`[REDACTED]`) находятся в защищенном хранилище n8n Credentials. При переносе на другой сервер n8n необходимо экспортировать/импортировать файл `credentials.json` с учетом его зашифрованного состояния.
