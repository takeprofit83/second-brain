### 1. Текущее состояние архитектуры
Проект реализован как **оркестратор на базе n8n**, управляющий пайплайном производства контента. 

*   **Интеграционный слой:**
    *   **Google Sheets:** Выполняет роль базы данных и конфигуратора. Хранит параметры генерации (настройки аватара, голос, ID видео) и финальные ссылки.
    *   **Google Docs:** Выполняет роль системы управления контентом (CMS) для хранения и правок сценариев.
    *   **n8n:** Ядро автоматизации, связывающее все API-вызовы через Workflow-цепочки.
*   **Workflow-структура:**
    *   **Workflow 5 (HeyGen/API Gateway):** Отвечает за инициализацию генерации. 
        *   *Логика:* Считывание параметров из строки Google Sheets -> Формирование JSON-payload -> Отправка POST-запроса в API генератора -> Запись `task_id` или `video_id` обратно в Google Sheets для отслеживания статуса.
    *   **Workflow 6 (Webhook Listener):** Отвечает за асинхронное получение результата.
        *   *Логика:* Прием POST-запроса от внешнего API (callback) -> Валидация `video_id` -> Обновление соответствующей записи в Google Sheets готовой ссылкой на скачивание.

### 2. Принятые решения и их обоснование
*   **Использование n8n как оркестратора:** Выбрано из-за гибкости визуального построения логики и легкости замены одного API-узла на другой без переписывания кода.
*   **Асинхронная модель (Webhook):** Принята из-за длительного времени рендеринга видео (генерация аватара занимает минуты). Использование Webhook позволяет не блокировать выполнение n8n в ожидании ответа сервера.
*   **Модульность генерации:** Принято решение не «зашивать» конкретный сервис в логику сценариев, а использовать промежуточный слой (параметризация через Google Sheets). Это позволяет переключаться с HeyGen на альтернативы (Kie.ai/OmniHuman) простым изменением настроек в таблице.
*   **Стратегия «Заглушка»:** Принята для экономии бюджета. Использование mock-данных вместо реальных платных API позволяет тестировать целостность цепочки (валидация колонок, прохождение данных между узлами).

### 3. Что сделано и проверено
*   **Настройка среды:** n8n подключен к Google Sheets API и Google Docs API. Доступы (Credentials) настроены через внутренние механизмы безопасности n8n.
*   **Инфраструктура хранения:** Созданы таблицы Google Sheets с необходимой структурой полей (статус, ID сценария, ссылка на результат, параметры генерации).
*   **Базовая логика:**
    *   Протестировано извлечение текста из Google Docs.
    *   Протестировано чтение параметров из Google Sheets.
    *   Настроена логика приема входящих Webhook (протестировано через Postman/curl).

### 5. План следующих шагов
1.  **Реализация «Менеджера генераторов»:** Создать в n8n логический узел (Switch), который смотрит в Google Sheets: если в поле «Provider» стоит «HeyGen» — идет вызов одного API, если «OmniHuman» — вызывается цепочка из двух запросов (TTS -> Видео).
2.  **Обработка ошибок:** Добавить в n8n ветку обработки исключений (Error Trigger), которая будет записывать ошибки API в отдельный лог-лист Google Sheets.
3.  **Автоматизация запуска:** Добавить расписание (Schedule) или триггер по изменению статуса в Google Sheets (например, появление слова «Готов к генерации» в колонке статус).
4.  **Валидация:** Настройка пре-чек-листа перед отправкой запроса (проверка длины текста в сценарии, чтобы не превысить лимиты API).

### 6. Нерешённые вопросы и ограничения
*   **Лимиты токенов:** Необходимо проработать механизм учета лимитов (баланса) внутри n8n, чтобы предотвратить попытки генерации при пустом балансе API.
*   **Синхронизация:** При использовании альтернатив (OmniHuman), где аудио и видео генерируются раздельно, необходимо внедрить этап «склейки» (например, через API облачных видеоредакторов типа Cloudinary или специализированных библиотек Python в n8n).
*   **Стабильность связи:** При сбоях Callback-сервиса видео может «зависнуть» в статусе обработки. Требуется внедрить периодический опрос (Polling) статуса задачи, если Webhook не пришел в течение 30 минут.
