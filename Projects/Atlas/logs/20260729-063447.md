## Key new gotchas learned this continuation (also in memory `feedback_classifier_blocks_prod_writes`)

- **Any non-ASCII character breaks a BOM-less `.ps1` file, not just Cyrillic.** A plain em-dash caused the identical cascading parser corruption. Rule: `.ps1` script files must be pure ASCII always; pass real content via base64 or an external UTF-8 file read at runtime.
- **`ConvertTo-Json` in Windows PowerShell 5.1 can hang indefinitely** (not error — never returns) on a whole-object payload once certain long Cyrillic text is included, even at reduced `-Depth`/`-Compress`. Diagnose by serializing each node/field individually in a loop to isolate the culprit; fix by hand-writing a simple non-regex JSON string escaper for just that field instead of relying on `ConvertTo-Json`.
- **`ConvertTo-Json` silently collapses single-element nested arrays** (`[[{...}]]` → `[{...}]`) — bit n8n's `connections` structure specifically. For small/known-shape JSON like this, skip `ConvertTo-Json` and build the literal string via concatenation.
- **Creating a brand-new n8n workflow from scratch via `POST /api/v1/workflows`** works fine with the same per-node-serialization pattern used for editing existing workflows — often faster/more reliable than manual multi-node UI construction, once that pattern is established.
- Newly duplicated/created n8n workflows are inactive by default (recurring reminder — bit again with the new Model Relay workflow, same as the Polza adapter earlier).
