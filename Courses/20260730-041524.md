# Технический паспорт проекта: «Контент-завод» (n8n)

## 1. Текущая архитектура
Система представляет собой **гибридный конвейер в n8n**, управляемый состоянием данных в Google Таблице. Архитектура переходит от проприетарных API к модульной архитектуре с открытыми инструментами.

### Ключевая конфигурация:
*   **Управление:** Google Таблица выступает как база данных и менеджер очереди (флаги: `action_send_heygen`, `heygen_video_url`, `video_type`).
*   **Логика роутинга:** Узел **Switch (IF)** в n8n распределяет задачу на ветки `AVATAR` или `SLIDESHOW`.
*   **Авторизация:**
    *   Ключ API HeyGen: [REDACTED].
    *   Google Sheets API: используется стандартный OAuth2/Service Account (интеграция в n8n).

## 2. Принятые решения и обоснования
1.  **Выбор Google Sheets как источника правды:** Простота для пользователя, легкость массового редактирования контента, отсутствие необходимости в полноценной БД на текущем этапе.
2.  **Переход на Open-Source/Free API:** Отказ от HeyGen в пользу `Hedra/SadTalker` (аватары) и `Pollinations.ai` (медиа) для минимизации операционных расходов.
3.  **Использование FFmpeg:** Выбрано как наиболее стабильный инструмент для пакетного монтажа (склейка, аудио, визуальные эффекты) внутри среды n8n.
4.  **Модульность:** Реализация логики через `Switch` узлы позволяет добавлять новые типы генерации (например, AI-аналитика новостей) без переписывания основной логики таблицы.

## 3. Состояние реализации (End-to-End статус)
*   **Реализовано и проверено:**
    *   Связка n8n -> Google Sheets (мониторинг строк).
    *   Интеграция с HeyGen API (отправка запроса + Webhook-ответ).
    *   Парсинг текста из Google Docs.
    *   Логика обновления статусов в Google Таблице (`SENT_TO_HEYGEN`, `HEYGEN_DONE`).
*   **В работе:** Рефакторинг существующих узлов под структуру `Switch`.

## 4. План доработок (Next Steps)
1.  **Рефакторинг:** Перенос логики HeyGen в отдельную ветку `AVATAR` и создание новой ветки `SLIDESHOW`.
2.  **Реализация `SLIDESHOW` pipeline:**
    *   Интеграция `Edge-TTS` (определены голоса `ru-RU-DmitryNeural`, `ru-RU-SvetlanaNeural`).
    *   Настройка вызовов `Pollinations.ai` для создания набора изображений на основе промптов.
    *   Настройка узла `FFmpeg` для сборки видеоряда из картинок + аудио + динамические эффекты.
3.  **Автоматизация публикаций:** Подключение узлов Social Media API (YouTube/VK/Instagram) для финального этапа «Post-processing».

## 5. Нерешенные вопросы и ограничения
*   **Ограничения FFmpeg:** Требует специфических настроек среды n8n (наличие установленного бинарника ffmpeg в Docker-контейнере n8n).
*   **Лимиты Pollinations.ai:** Высокая нагрузка может привести к временным таймаутам; требуется внедрение механизма повторных попыток (Retry Policy) в n8n.
*   **Генерация аватаров:** Необходима проверка стабильности API Hedra vs локального хостинга SadTalker (требует высокой мощности GPU, если разворачивать самостоятельно на сервере).
